## 1단계: 분석 기반 교체 ✅ 완료

초기 분석은 대조군 설정에 문제가 있었습니다(아래 표). 그래서 상황을 매칭한 대조군과 diff-in-diff를 쓰는 새 분석 코드로 기반을 바꿉니다. 초기 분석은 지우지 않고 시행착오 기록으로 남깁니다.

| 초기 분석의 문제 | 새 방식 |
|---|---|
| 대조군에 아웃·삼진·단타를 모두 넣음. 삼진의 마지막 공은 2스트라이크 결정구이고, 단타는 그 자체로 나쁜 결과라 장타와 비교하기에 성격이 다름 | 대조군은 **타구가 나왔지만 아웃된 경우(`field_out`)**만 씀 |
| 측정 타석의 T 비율을 **수준**으로만 비교함. 그 투수가 원래 T를 얼마나 던지는지(baseline)를 빼지 않아, 집단 간 구종 구성 차이(장타군 T의 포심 비중 36.2%, 대조군 30.7%)가 결과에 섞일 수 있음 | baseline(시즌 구사율, 경기 내 직전까지 구사율) 대비 변화를 구하고 대조군 변화를 뺌(**diff-in-diff**) |
| 장타군과 대조군의 시즌·구종 분포를 맞추지 않음 | 시즌 × 구종계열로 **층화추출**해 1:1 매칭 |
| 경기 상황(주자, 아웃, 이닝, 카운트, 점수차)을 통제하지 않음. 장타는 위기 상황에서 더 자주 나옴 | **상황 매칭 사다리 M0 → M3**로 단계별 통제 |

## 5단계: 분석 점검

보고서를 쓰기 전에 지금까지의 분석을 냉정하게 다시 봅니다. "장타 뒤 그 구종을 덜 던진다"는 현상은 상황을 통제해도 일관되지만, **왜 피하는지**와 **그 타자에게 맞춘 회피인지**는 아직 증명되지 않았고, 신뢰구간은 실제보다 좁게 계산돼 있습니다. 아래 항목으로 이 빈틈을 메웁니다.

### 필수

| # | 문제 | 할 일 |
|---|---|---|
| A1 | **그날 그 구종이 나빴다는 설명을 배제하지 못함.** 장타는 실투나 구위가 떨어진 공에서 더 자주 나오고, 대조군(`field_out`)은 평균적으로 더 좋은 공이라, 장타와 회피가 같은 원인(그날 구종 상태)에서 나왔을 수 있음 | 장타 **이전**까지 그 경기에서 그 구종의 구속(시즌 평균 대비), 헛스윙률, 피타구 xwOBA를 매칭 변수나 공변량으로 넣고 회피가 남는지 확인 |
| A2 | **"그 타자에게 맞춘 회피"라는 증거가 없음.** 재대결(14%p)과 다음 타자(7%p)는 모집단이 달라(재대결은 주로 오래 던진 선발, 다음 타자는 2아웃 제외·다음 타석 주자 차이) 직접 비교할 수 없음 | **같은 장타 이벤트 안에서** 재대결 전까지 상대한 중간 타자들의 T 비율과 재대결 타석의 T 비율을 비교 |
| A3 | **신뢰구간이 실제보다 좁음.** 순수 감소와 타구 질 분위표의 CI는 이벤트가 서로 독립이라고 가정하지만, 같은 투수·경기의 이벤트가 반복해서 들어감. 또 대조군을 시드 1개로 한 번만 뽑아 추출 변동이 반영되지 않음(같은 M0인데 오즈비 0.286 vs 0.304) | 투수 단위 cluster 부트스트랩으로 CI를 다시 내고, 대조군을 여러 시드로 반복하거나 칸별 가중치로 조건에 맞는 `field_out` 전체를 사용 |

### 권장

| # | 문제 | 할 일 |
|---|---|---|
| B2 | **측정 단위의 잡음과 내생성.** 비교 타석의 26%는 투구 1~2개라 비율이 극단값이 되고, 볼카운트 흐름과 타석 결과가 측정값에 영향을 줌 | 재대결 **초구만** 따로 보거나, 투구 단위로 카운트를 통제한 모형으로 확인 |

## 예비 계획: Run Value

Run Value 변수는 처음에 점수차와 함께 추가할 계획이었습니다. 하지만 회피가 있는지 확인하는 분석(M0~M3)에는 쓰이지 않고 **회피의 합리성 평가(GBM)** 단계의 재료라서, 그 단계를 계획할 때 함께 진행합니다.

| 항목 | 내용 |
|---|---|
| 쓰임 | 투수의 실제 구종 선택이 Run Value 기준으로 합리적이었는지 평가, GBM 변수 후보 |
| 문제 | 현재 CSV에 run value 컬럼(`delta_run_exp`)이 없음 |
| 방법 후보 | ① 데이터 안의 주자·아웃·점수 변화로 시즌별 RE24 기대득점표를 만들어 투구별 run value 계산<br>② run value가 들어간 CSV를 새로 받기 |
| 시작 시점 | 6단계(보고서) 이후, 합리성 평가 단계를 계획할 때 |
| 확인할 것 | 계산값이 상식과 맞는지 (장타는 크게 양수, `field_out`은 음수) |
